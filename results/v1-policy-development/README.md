# 策略评测接入：开发证据

日期：2026-10-13。只验证策略在原生/生成实例上的实际接入，不是冻结的论文实验或官方榜单复现。
机器可读数据见 [summary.json](summary.json)，部署、审计和运行命令见
[策略评测说明](../../docs/policy-evaluation.md)。

## 固定输入和执行条件

- 任务为完整 `stack_blocks`，机器人为原生 `arx_x5` 双臂。
- 原生输入为 layout 0；生成输入为此前语言流程导出的六杂物实例，reset seed 1200。
  生成 episode 哈希为 `3b8a0a75a5c96a66d4302ad4e6600b56c8713dd59c2b20fc6e456c89944653a0`。
- 输入在策略执行前选定，两个策略共用这两份输入；开发样本不代表完整实例分布。
- 每局 550 个原生动作上限，25 Hz 观测，物理步长 0.004 秒；使用原生插值、终止和评分。
- 策略仅接收原生三路 RGB、本体状态、前次控制和任务指令，不接收生成参考轨迹或 event。
- RoboDojo 与 XPolicyLab 版本、实际输入输出、代码和权重哈希随运行归档。

## OpenWAM 单次真实推理

完整 step-60000 checkpoint 在固定 XPolicyLab 副本加载，使用明确命名的
`OpenWAM-step60000-cpu-text-bf16` 部署条件：文本编码器在 CPU，其余参数在 GPU，
保留 BF16、10 次同步去噪和完整动作 chunk。没有使用 dummy policy。

第一次完整模型诊断已加载权重，但配置归档解析未使用的训练日期表达式失败；未执行动作推理。
保留该次故障，归档改为保留配置表达式。第二次诊断在同一份已记录原生观测上输出
32 步双臂 EEF 动作，耗时 6.912 秒，PyTorch 峰值分配 13,635,970,048 字节。
这里没有同时运行仿真，峰值不代表部署与仿真共用 GPU 时的总占用。
这是推理接入证据，单独不能证明任务完成或策略得分。

## OpenWAM 完整开发配对

代码版本 `592d895`，两局使用同一个真实权重服务，均正常退出并通过结果审计：

- 原生 layout 0：执行 550 个动作，原生过程分 **15/100**，完整任务失败；
  evaluator 计时约 272.40 秒。
- InfiniDojo 六杂物实例：执行 550 个动作，原生过程分 **15/100**，完整任务失败；
  evaluator 计时约 267.27 秒。

上游单环境适配器将最后一个 32 步 chunk 的剩余动作提交给已结束的环境；
每局共请求 576 次，其中 26 次被原生 evaluator 忽略。有效动作始终为 550，
没有延长预算或在终止后推进额外操作。实际输入输出及三路原生视频均已归档。

审计核对两局的模型部署、执行配置、相关源码一致，核对输入布局、权重来源、图像哈希，
并确认完整原生结果与汇总一致。**这证明该生成实例能进入真实策略评测和原生评分流程。**
两例相同的过程分不代表轨迹相同，也不能推出两类实例一样难；没有据此更换场景或追加策略预算。
策略未完成任务不等于实例无解，生成实例先前的参考验证与此次被测策略结果分别保留。

## Astra 首次开发配对

使用已有 `GPT_6_Astra_Codex_EEF` 传输，请求 `gpt-6-astra`、medium reasoning；
每局最多 100 次模型调用，两次观测图像历史、无深度，单次服务超时 240 秒。
它与官方 Direct EEF API 条件存在提示/传输差异，不标记为官方 API 复现。

原生局完成 74 次调用与 295 个实际动作，第 75 次调用遇到账号额度耗尽；
生成局在第 1 次调用遇到同一错误，没有执行策略动作。两局均没有有效最终成绩。
所有请求保留，不能将它们计为成功率为零，也不能使用部分进度替代完整结果。

原生局记录的模型调用延迟合计约 1,829.97 秒，生成局失败调用约 14.44 秒。
成功 CLI 回合报告的输入/输出 token 分别为 2,798,382 / 15,442；
失败回合没有完整 token 用量，未知部分不视为零费用。

审计核对了两局的共同模型/执行配置及相关源码，并验证记录的 RGB/JPEG 内容与实际动作计数。
Kit 关闭后两进程均返回 0，但显式错误及缺失的完整原生评分使两局保持基础设施故障状态。
审计没有把退出码当作成功证据。
