# 场景感知规划接入：开发证据

日期：2026-10-12。以下均是开发诊断，不是正式 G1/G2/G3 比较，也不是策略评测。
论文主张与停止条件仍以 [投稿版本约定](../../docs/paper-contract.md) 为准。

## 本次完成的能力

原生 CuRobo wrapper 的世界只有桌面，球模型没有夹指。新增 `--scene-aware` 入口，
复用同一个 CuRobo 规划算法，将真实物体、桌面、固定设施和另一机械臂纳入规划。
夹指几何按实际开合状态更新；稳定持物阶段使用随末端运动的目标几何；释放后恢复为静态障碍。
这些只改变规划模型，执行中没有焊接或瞬移。

最终版本在已有六杂物布局上完成 13 次运动规划、16 个交互阶段和返回初始位置，
原生任务得分 100，24 项独立开发检查全部通过。该布局原先由 G2 产生，这次重新在线规划，
用途是检查共用规划器接入，不能把它当作一次新的 G2 正式实验或独立生成样本。
原有 Infinigen 资产和布局来源见 [补全结果](../v1-completion-development/README.md)。

新增的 `--initial-state-only` 入口只使用 reset 时的状态采样静态候选，不使用后续参考动作。
一个请求六杂物、三组成对关系的开发候选在 16 次布局提案后满足初始约束，在线执行到
第一次放置时规划失败。共同验证结果为 `unverified`；不判定该场景不可解。
总预算内重试循环尚未完成，因此 G1 仍是部分实现。

## 全部物理运行及修正

逐次结果见 [execution-rows.json](execution-rows.json)，每次运行保留来源哈希、原生结果、
规划摘要与原始文件索引；全部原始控制、状态和接触日志保存在各 `raw-artifacts.json`
指定的本地输出目录。不同实现版本的调试运行不能合并成成功率。

1. `native-1200-attempt01`：创建了未使用的批量规划器，显存不足，记为基础设施错误。
2. `native-1200-attempt02`：第一阶段规划拒绝。探针定位到底座球与桌面的约 14.3 nm 数值重叠。
3. `native-1200-attempt03`：限制固定底座球下沿、仅创建所需规划器后，全任务成功，24 项检查通过。
4. `g1-candidate-1200-6-execution`：初始布局符合请求，前四次运动规划成功，放置规划失败，未验证。
5. `g2-layout-online-1200-6`：已有六杂物布局在线规划成功，24 项检查通过。
6. `g2-layout-online-1200-6-fixtures`：补入相机支架并从配置读取桌面后重跑，成功且 24 项检查通过。

前五次运行的规划世界未包含固定相机支架，作为开发历史保留。最终第六次包含它；
不能将早期运行追溯性标记为具有最终版本的碰撞覆盖。
最后一次运行包含 5,613 个 4 ms 物理步，冷启动到完成约 67.50 s。
规划 FK 与实际末端坐标的最大位置误差约 0.000304 mm；这是该运行的坐标接入检查，
不能推广为机器人模型整体几何精度。

## 持物几何是否真正影响规划

[可复现探针结果](payload-probe-portable/result.json) 在同一次已完成的搬运任务上控制变量：

- 原场景：规划成功。
- 在持物目标位置加入 14 mm 虚拟方块：规划失败。
- 保留同一方块，仅诊断性关闭持物球：规划成功。
- 移除方块并恢复持物球：规划成功。

虚拟方块在基准目标姿态下距其余机器人球仍有约 7.14 mm 间隙。
因此该探针支持“世界更新和持物几何被规划器实际使用”，不只证明接口调用没有报错。
它不是真实碰撞执行、不计作生成实例，也不代表所有障碍都可绕开。
早期数值问题探针见 [probe01.json](probe01.json)。开发脚本第二次探针在写 JSON 时失败，
日志和源文件保留在 `outputs/v1-planning-development/probe02.*`；修复后的重复结果见
[probe03.json](probe03.json)。最终公开模块已在含固定设施的执行上运行并通过四种条件。

## 边界与后续工作

规划碰撞输入使用 OBB 和覆盖球；它们可能误拒绝真实可行轨迹。固定底座球下沿离底座
支撑平面 0.1 mm，避免固定支撑接触被浮点误差判为碰撞。其余运动连杆没有这一豁免。
持物与支撑面的合法接触通过阶段规则处理：优化器暂时省略该支撑，候选再对其他链接—支撑
碰撞复查。物理验证独立检查真实接触和穿透；规划通过不等于实例有效。

本次只覆盖原生右臂堆叠及三个已生成的 CanFactory 杂物资产，没有新增方法创新点。
全部结果为开发种子 1200，不提供效率优势或泛化结论。开发验证仍有采样分辨率、几何近似
和初始化接触历史等限制，详见 [任务契约](../../specs/tasks/stack_blocks.json)。

下一步是 G1 的有界生成—规划—验证—重试，以及基于实际失败约束的最小 G3 关联调整。
其后仍须完成语言前端、其他约定任务、正式冻结实验及两策略跨实例集合评测。
