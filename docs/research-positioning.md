# 论文定位与比较对象

## Motivation 与方法

InfiniDojo 面向 **RoboDojo 上可定制场景复杂度的具身操作评测实例生成**。
用户指定任务以及物体、布局、空间关系等场景条件，系统生成可复现的评测实例。
这沿用 InfiniBench 从若干预设 benchmark 转向可定制 benchmark generator 的思路；
论文应引用这一来源，并用操作评测的相关工作具体支撑可定制性不足的论断，
不直接宣称所有已有 benchmark 都无法进行条件控制或失败分析。

操作领域需要布局支持完整交互。我们研究在最小任务场景中建立参考操作，
按 interaction event 组织机器人与物体的关系，再围绕这些关系补全场景。
操作可行性是实例的有效性要求；失败模式分析和 RSI 保持为下游用途。

两个组成部分是语言驱动的约束/事件生成与修正，以及按交互事件组织 cluster 的场景生成。
贡献重心在后者：保持运动、接触、支撑关系，关联调整物体，必要时在允许范围内更新任务位置
和参考动作。这是下一阶段的研究假设，尚未验证为新算法。

cluster 是共同受约束的对象集合。机械臂仍由关节驱动，只有稳定抓取时才保持夹爪与物体的
相对变换；释放后转入相应支撑关系。各阶段使用同一初始场景，阶段连接也要检查。
参考轨迹为生成和验证内部信息，被测策略自由决策。

Infinigen 提供程序化资产和可利用的关系约束；RoboDojo 提供机器人、物理环境、任务接口和评分。
按需接入 Infinigen 的能力，不把修改其完整求解器或增加联合优化器作为贡献成立的前提。

## 要证明什么

1. **描述能落地。** 生成实例保留用户要求的物体数量、尺寸、区域和任务语义；
   修正无效约束时不能通过减少杂物或扩大区域来偷偷放宽要求。
2. **场景支持完整操作。** 初始布局不重叠并不意味着后续抓取、搬运可行。
   与“先生成再规划重试”和“固定轨迹补全”比较，在相同总预算下检验有效产出、成本与覆盖。
3. **扩展评测有实际价值。** 同时报告生成时间、拒绝率、资产与布局多样性，
   后续再验证不同模型在这些场景上的表现。模型失败分析与 RSI 都是下游用途。

## 与什么比较

- [InfiniBench](https://arxiv.org/abs/2511.18200) 是生成流程的直接设计参考。
  后续应将它的静态布局优化思路适配到相同操作任务，与交互约束优化比较；
  VLM 空间推理准确率和机器人操作成功率不能直接放在同一列比较。
- [Infinigen Indoors](https://arxiv.org/abs/2406.11824) 是资产和约束生成基础。
  比较时固定资产来源，才能区分改进来自交互方法还是不同资产质量。
- [Sceniris](https://arxiv.org/html/2512.16896v1) 已支持高效程序化布局与可选机器人可达性检查；
  “添加机器人约束”本身不构成充分的新颖性论证。
- [DynScene](https://openaccess.thecvf.com/content/CVPR2025/html/Lee_DynScene_Scalable_Generation_of_Dynamic_Robotic_Manipulation_Scenes_for_Embodied_CVPR_2025_paper.html)
  涉及文本驱动的静态场景与动作轨迹生成，是动态操作场景生成的直接相关工作。
- [Steerable Scene Generation](https://arxiv.org/abs/2505.04831) 是进一步做场景生成
  方法对照的候选。需要统一任务、资产、请求、检查器和预算后再比较。
- [RoboTwin 2.0](https://arxiv.org/abs/2506.18088) 与任务脚本、随机化和机器人数据
  生成有关。可适配其任务条件随机化，但不能把跨模拟器的公开成功率当作公平对照。
- [RoboCasa365](https://arxiv.org/abs/2603.04356) 更适合比较任务覆盖和评测接口。
  [Logic-Geometric Programming](https://argmin.lis.tu-berlin.de/papers/15-toussaint-IJCAI.pdf)
  则是阶段切换、抓取附着等表示的已有方法背景，这些表示本身不应被宣称为新发明。

## v0 实际做的比较

本仓库实现三个受控对照：`independent`、`static`、`interaction`。
它们共享资产、请求、种子和预算，只改变布局检查是否考虑初始状态或完整参考交互。
这些是仓库内实现的基线，**不是上述论文的复现结果**。

v0 的 interaction 方法在已验证的参考动作下调整杂物布局。机械臂各连杆分别运动，
抓取建立后才使用夹爪—物体相对变换。它尚未实现任意任务的轨迹—场景联合优化。
碰撞审计覆盖机器人及目标与新增杂物之间的关系；固定机器人自身和场景设施的
可行性依赖原生规划器与参考执行，不将采样包围盒检查描述为完整物理证明。

第一轮实验用于确认链路与研究假设是否值得继续。论文级实验还需要更多操作任务、
不同资产形状与尺度、更长的交互序列，以及实际适配后的相关生成方法对照。
如果语言测试全部一次通过，应直接报告这一事实；它不能证明迭代修正优于一次生成。

v0 的 conservative usable yield 包含参考轨迹和执行轨迹的包围盒审计；
它是该试验的保守操作性指标，不能等同于场景无解/可解的判定。
历史协议、结果和冻结代码保持原样。后续方法、共同验证口径、实验设计与完成标准见
[下一阶段任务](next-stage.md)。
