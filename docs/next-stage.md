# InfiniDojo 后续研究与停止条件

更新：2026-10-13。**有限技术路线已打通；正式论文实验尚未完成。**
本计划取代旧版以扩展 G3 为重点的阶段清单。历史实现与正负结果保留，
[v0 协议](evaluation.md)及[v0 结果](../results/v0-pilot/README.md)不变。
研究范围以[投稿版本约定](paper-contract.md)和用户最新要求为准。

## 1. 核心定位

**按自然语言需求生成能够直接用于 RoboDojo 评测的实例，围绕外观、关系和组合复杂度提供控制。**

生成器必须在构造场景时考虑操作可行性。方法的落点是：先实例化任务物体及其交互，
再在不破坏该交互的约束下补全场景。最终物理执行检验这一构造是否有效，
不把增加后验检查当作核心技术贡献。失败模式分析和 RSI 是下游用途。

最小路线：

> 自然语言 → 有界场景约束 → 实际任务资产 → 完整参考交互 → 受约束的场景补全 → RoboDojo episode。

内部参考只证明有一种已执行的完成方式，不要求被测策略模仿，也不向策略暴露参考动作。
请求不受支持、未找到参考、未找到布局和基础设施故障分别保留；不能静默放宽请求。

## 2. 已支持什么

统一 `scene-v2` 入口覆盖 `general_pickup`、`stack_blocks`、`cover_blocks`，
机器人为原生 `arx_x5`。堆叠和覆盖均保留完整原生任务及返回要求。
详见[语言入口与参数边界](language-frontend.md)。

- **Appearance：** 五种具名材质颜色及目标/干扰物颜色相似度。开发配对只改颜色，
  目标与杂物几何、参考控制及最终布局保持相同。尚无纹理、灯光或相机控制。
- **Relational：** 成对距离、绝对区域、相对指定任务物体初始中心的区域。
  同一放置提案同时满足全占地范围与运动空间约束，绝对/相对区域须同时成立。
- **Compositional：** 干扰物数量与任务物体/干扰物组成；当前只支持一种共同罐体规格，
  不把数量控制说成任意类别组合，更不以 event 数量替代场景组合复杂度。

这些是可控参数，不预设某一设置必然更难。论文须明确每条轴实际操纵什么，
控制成功、实例可用和被测策略得分分别报告。

Infinigen 的最小接入已完成：CanFactory 生成拾取目标和干扰物，目标半径参数
1.8–3 cm、高度 5–9 cm；新几何先进入最小任务场景，再获取对应参考。
此接口范围不等于所有组合都有可行性证明。堆叠方块与空心覆盖杯保留原生资产，
不为路线完成强行扩展到新资产家族或空腔导出器。

## 3. event / interaction cluster 的准确作用

Event 表达操作阶段：接近、抓握、搬运、放置、释放及撤离；同时明确当前允许接触、
持物关系和支撑关系。释放后物体处于新位置，并影响后续操作。不同 event 共享同一个场景。

Interaction cluster 是共同受约束的机器人连杆、夹爪、操作物体及相关支撑物的集合。
它不是把整条机械臂刚性绑成一个物体；仅稳定抓取阶段的物体与夹爪可保持相对变换。
这些语义帮助构造完整参考、处理合法接触和记录阶段状态。

**当前的实质实现仍是完整参考条件下的场景补全。** 补全器检查参考中机器人和任务物体
的逐帧占据，增量加入满足区域/成对关系且不侵入操作空间的物体。
Event 标签用于阶段组织与冲突归属；在保留全部逐帧几何后只删标签，不会形成独立的
布局优化方法对照。因此不以重新命名 cluster 来宣称超越固定参考轨迹预留。

现有方法已经把约束前置，但目前使用离散几何近似，不能保证任意请求都可构造，
也不能证明连续运动与完整接触动力学。物理执行是构造机制的实验检验。
如果未来要主张独立的 event 优化算法，必须有额外的可操作自由度及对照证据；
它不属于这轮技术路线打通的必要工作。

G3 已有一次位置修复的运行证据，固定参考重试也能成功，未发现效率优势。
保留[已有结果](../results/v1-pickup-retry-development/README.md)，冻结启发式，
不扩展覆盖任务的 G3，也不为寻找优势更换条件。

## 5. 最少的论文证据与后续顺序

先写方法和能力边界，再冻结一次有限正式实验。使用已有任务、资产和机制，
不继续扩建方法。正式清单需明确场景族、参数、预算、阈值和统计方式；不能根据结果选种子。

1. **描述到可控实例。** 冻结基准、外观、关系、组合和联合条件，在保留场景族上运行。
   报告语言符合度、实际生成参数、成功/失败及成本；自然语言表述与几何条件分别核对。
   外观控制保留配对几何/布局，复杂度影响不能仅凭档位名称推断。
2. **生成中的可行性。** 在同一批实例上报告第一次完整构造与有界重试后的物理有效性，
   检查完整原生任务及阶段连接，保留所有失败。若需要证明约束前置的作用，
   仅在现有 G1/G2 均支持的拾取和堆叠任务上作“先布景后规划 / 参考条件补全”对照，
   共享请求、资产、规划器及总预算；不为覆盖任务另造基线，不要求 G2 必须更快。
   G3 已有诊断足够，不再添加独立修复实验；不做仅删 event 标签的无效消融。
3. **直接评测的用途。** 固定 OpenWAM 与 XPolicyLab GPT-6 Astra 的各自部署，
   两者分别评测原生与生成实例；模型、观测、控制适配和原生动作预算在同一策略两组间固定。
   在看策略成绩前固定输入选择规则。当前 OpenWAM 接口已通，Astra 历史额度故障仍需解决，
   不能把缺失评分记成策略失败。详见[策略接入](policy-evaluation.md)。
4. **复现与写作。** 发布配置、逐请求结果、版本/资产来源和生成命令；大文件按许可提供来源。
   根据结果写成可控评测生成流程贡献。模型得分下降、排名反转或生成效率优势均非必要结论。

其中第 2 项的机制比较解释构造约束，第 3 项比较两个被测策略；不混淆二者。
统计以场景族为单位，同族条件和轨迹帧不是独立样本。原生/生成分布不同，
跨集合差值不能直接当成某一个复杂度因素的因果效应。

## 6. 到哪里停止

近期“把技术路线打通”的工程目标已达到，停止新增模块。
论文阶段完成上述冻结实验及复现材料后进入结果写作，不因为未看到优势继续加启发式、
换模型或扩展任务。修复明确的实现错误须记录版本并重跑受影响条件。

若无 event/修复的额外收益，就保留其必要工程语义，收缩算法主张；
若有限范围内生成控制与实例可用性本身不足，则如实报告核心主张的缺口。
写作可以现在开始，正式论文主张须等待批量证据；工程路线完成不等于论文实验完成。
