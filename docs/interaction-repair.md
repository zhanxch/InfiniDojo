# 有界的交互位置修复

这是针对固定参考补全失败的一次最小方法实现，尚不是已证实有相对优势的算法。
开发依据是十二杂物请求的失败记录：部分候选与完整参考占用冲突，另有区域越界和杂物重叠。
改变任务位置只可能改善第一类问题，不保证请求能完成。

## 请求与共同搜索范围

可选字段 `task_xy_options_m` 为任务物体分别列出允许的初始 XY 位置：
堆叠任务包含三个原生方块，拾取任务包含 `target`。
每个物体最多九个选项；单个选项表示位置固定。所有方法使用同一份请求。
未声明此字段时不能移动任务物体，G3 退化为固定参考补全。

首个开发请求只允许堆叠底座 `block_0` 从原位置向四个轴方向移动 6 cm，
另两个方块固定。杂物数量、资产身份、区域、间距及成对关系保持原请求值。
这是新增了明确位置自由度的请求，不能与此前位置固定的请求混称同一实验条件。
位置选项是开发配置；正式范围需经开发诊断后冻结。

给定原生布局的任务物体位置若在允许选项中，三个方法从同一布局开始；否则按相同种子
选择允许配置。G1 的布局重试可以从未试过的允许配置中均匀重采样，并获取新的 reset 状态；
G2 保留首个完整参考；G3 在场景补全失败后至多提出一次关联位置变更。
G3 的 `--disable-repair` 消融保留首个参考，执行流程应与 G2 一致。

## 从冲突到交互位置

场景补全继续检查整段实测参考的机器人连杆、任务物体和固定设施几何。
发生运动占用冲突时，额外记录涉及的 event 和物体/连杆身份。
这些记录不改变原来的候选接受条件。

支撑/交互关系决定哪些初始位置可能影响冲突：

- 接近、下探、抓握和抬升关联当前操作物体的来源位置。
- 搬运关联来源与目标支撑位置；放置、释放和撤离关联目标支撑位置。
- 已释放物体继承新的支撑位置。第一次把 `block_1` 放到 `block_0` 后，
  第二次放置 `block_2` 的目标由 `block_0` 的位置决定。
- 拾取以持物结束，抬升和保持阶段都关联目标的来源位置；不为统一接口增加释放阶段。
- 被动任务物体按当时支撑关系追溯位置；固定设施、机器人底座及另一机械臂
  不为任务位置修复提供投票。

对每个可调位置，收集与上述关系有关的被拒杂物 cluster 中心。每个候选 cluster
对一个位置最多计一次，不按轨迹帧数或碰撞连杆数重复加权。
在请求允许的位置中，选择平均增大与这些冲突中心距离最多的一项；没有正向候选则不修复。
这是方向性搜索启发式，不是关节运动预测，也不证明新位置更可行。

## 更新与验证

位置只在新的初始场景中设置。机器人底座、关节模型、物体身份、几何、朝向、初始高度和
任务顺序保持不变。随后使用共同规划器重新规划并物理执行整个任务：堆叠包含后续放置、
返回和稳定保持，拾取包含抬升与持物保持；不平移旧的机械臂轨迹，不在执行中瞬移或焊接物体。

只有新参考完成原生任务，才用它重新补全场景。最终含杂物场景仍需实际执行和共同验证，
额外检查初始化后的任务物体位置属于请求选项，再允许导出评测 episode。
被测策略不接收参考控制、event 标注或修复依据。

修改记录包括冲突来源、候选排序、修改前后位置、关系依赖、规划/执行及验证结果。
全部步骤计入同一请求预算；新参考失败、候选不足或超时都保留，不能放宽请求来接受。
目前采用整段重规划，关系依赖用于选择修改对象，不声称已经实现阶段轨迹复用。

## 本轮的判断边界

本轮先检查完整闭环、位置约束、支撑传播和禁用修复的退化行为。比较对象使用共同
请求与预算，但单一开发种子不能证明 G3 总体优于 G1/G2。
如果修复无效，就记录其限制；不继续堆叠抓法搜索、学习模型或新规划器来追求正结果。
任务/语言前端覆盖与真实策略评测仍按投稿约定推进。

拾取接入使用原生直立罐体与既有 45° 抓法；持物覆盖球仍使用 1 cm 网格单元，
仅按实际操作物体预分配足够容量，避免沿用小方块的 125 个槽位上限。
当前目标需要 350 个球，几何没有被缩小、截断或改用更粗分辨率。
开发范围和七组运行配置见 [拾取生成约定](../specs/v1-pickup-retry-development.json)。
覆盖任务的杯腔与双臂场景规划尚未接入此统一执行器，不能套用实心盒子持物模型。
